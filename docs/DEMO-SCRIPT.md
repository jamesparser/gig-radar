# Demo video — shot list (target 3:30, hard limits 2:00–5:00)

A human records this (screen + voice). It is written so every claim on screen is true: no real marketplace listings, no fake numbers, Stripe visibly in **test mode**.

**One line to land:** *GigRadar finds the gigs that fit and drafts the pitch — you close the deal.*

## Before recording

- Deployed HTTPS URL, Stripe test keys, a fresh account (`demo+<date>@…`) with no history. Browser zoom 110%, bookmarks bar hidden, notifications off.
- Extension built against the deployed origin and loaded unpacked, **not** yet connected (so you can show setup).
- Second tab: the Stripe test-mode dashboard (to show the webhook delivered) — optional but strong for "Monetization".
- Free-quota demo needs a fresh account; the Pro part continues on the same account after checkout.
- An LLM key set if you want to show "Generated by anthropic:…"; otherwise say "template mode" aloud — it's honest and still shows the loop.

## Must-show for the judging rubric

- **Technical architecture:** the README diagram; mention extension → API → scorer/LLM/Postgres, signed license keys, idempotent webhooks.
- **Governance & compliance:** human-in-the-loop moments (Scan press, inert Submit, checklist), Privacy page, Export/Delete.
- **Product innovation:** the "what you still must do" checklist and honest placeholders; unknown ≠ bad scoring.
- **Monetization:** Checkout → webhook → license → gate, with the three tiers.
- **UI/UX:** the badges in-page, score ring and reasons, one-click copy.

## Don'ts

- Don't show a real marketplace page with GigRadar badges unless you have verified the parser works and you are comfortable with that site's terms. The fixture board is the honest demo.
- Don't say "automatically applies", "beats detection", or imply revenue/customers. There are none.
- Don't leave `localhost` visible in the address bar or the extension's API field.
- Don't show real card numbers — only Stripe's `4242 4242 4242 4242`.
